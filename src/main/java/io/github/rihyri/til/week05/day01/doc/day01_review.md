# Week 5 - Day 1. 회고

<br>

오늘은 HTTP의 `Stateless` 특성을 이해하고, 서버가 사용자 상태를 유지하기 위한 `Cookie`와 `Session`의 개념을 학습하였다.

또한 `HttpSession`을 이용한 데이터 저장과 조회, 세션 기반 로그인 및 로그아웃 기능도 살펴보았다.

이해한 내용을 다시 살펴보자.

### 1. Cookie와 Session은 함께 사용될 수 있다.

개발에 처음에 접했을 때 쿠키와 세션 중 하나를 선택해야 하는 것인지 헷갈렸다. 일반적인 세션 기반 인증에서는 서버에 상태를 저장하고 브라우저의 쿠키로 세션 ID를 전달한다는 차이를 다시 이해할 수 있었다.

### 2. 세션을 통해 HTTP 요청 사이에서 사용자 상태를 유지할 수 있다.

로그인 후 세션에 사용자 ID를 저장하고, 다음 요청에서 이를 조회하는 흐름을 코드로 확인하였다.

### 3. 서버가 여러 대라면 세션 공유를 고려해야 한다.

로컬 세션만으로는 다른 서버가 사용자의 상태를 확인하기 어렵기 때문에 `Sticky Session`, `Session Replication`, `중앙 세션 저장소`와 같은 방식이 필요할 수 있다.

<br>

이번 학습을 통해 로그인이 단순히 회원 정보를 조회하는 기능이 아니라, 인증 결과를 이후 요청에서 유지하도록 관리하는 과정임을 이해하였다.
