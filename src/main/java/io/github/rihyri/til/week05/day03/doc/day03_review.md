# Week 05 - Day 02 : 학습 회고

<br>

이번 수업에서는 Redis를 활용한 캐싱 전략과 데이터 관리 방법을 학습했다.

Redis가 단순히 데이터를 빠르게 조회하는 저장소가 아니라, 데이터의 조회 및 변경 방식에 따라 다양한 캐싱 전략을 적용할 수 있다는 점을 알게 되었다.

특히 `Cache-aside`, `Write-through`, `Write-back`, `Write-around`의 차이를 살펴보고 각각 어떤 상황에서 활용할 수 있는지 학습했다. 

추가로 TTL과 LRU/LFU를 통한 메모리 관리, RDB와 AOF를 활용한 데이터 영속성도 공부했다.

<br>

가장 이해하기 쉬웠던 전략은 `Cache-aside`였다.

먼저 Redis를 조회하고, 데이터가 없다면 DB에서 가져와 캐시에 저장한다는 흐름이 명확했다.
또한 Write-around에서는 데이터를 수정한 뒤 캐시를 삭제해야 한다는 점이 중요하게 느껴졌다.

Write-through는 DB와 캐시를 함께 갱신하고, Write-back은 DB 반영을 뒤로 미룬다는 차이가 있었다.

특히 DB 트랜잭션과 Redis 작업이 자동으로 하나의 트랜잭션으로 처리되지 않는다는 점이 중요했따.

Redis에 저장된 데이터가 DB와 달라질 수 있기 때문에, 캐시를 언제 저장하고 언제 제거해야 하는지 함께 고려해야 한다는 것을 알게 되었다.

<br>

Redis를 처음 배울 때는 데이터를 빠르게 저장하고 조회하는 기능이 핵심이라고 생각했다.

하지만 오늘 수업을 통해 캐싱은 속도뿐 아니라 데이터 일관성과 장애 상황까지 고려해야 한다는 것을 알게 되었다.

앞으로 Redis를 사용할 때 단순히 캐시를 적용하는 것에 그치지 않고, **왜 해당 캐싱 전략을 선택해야 하는지** 생각하면서 구현해야겠다.
