# Week 3 - Day 3. 회고

<br>

이번 수업은 지금까지 들었던 수업 중 Service 코드가 가장 어렵게 느껴졌다.

단순히 데이터를 조회하거나 저장하는 Service와 달리, 이번에는 사용자의 메시지를 DB에 저장하고 이전 대화를 다시 조회한 뒤 Spring AI의 Message 타입으로 변환해서 AI에게 전달하는 과정까지 한 번에 들어가 있어서 흐름을 따라가기 어려웠다.

이번 수업에서 가장 중요하게 느낀 부분은 LLM도 대화를 계속 기억하는 것이 아니라 애플리케이션이 DB에 대화를 저장하고 필요한 Context를 다시 만들어 전달해야 한다는 점이었다.

또한 모든 대화를 계속 전달하면 Token과 비용이  증가하기 때문에 오래된 메시지는 요약하고 최근 메시지는 그대로 유지하는 Sliding Window 방식도 알게 되었다.

아직 Service 전체를 혼자 작성할 수 있을 정도는 아니지만, 우선 코드를 외우기보다는

**대화 저장 → 이전 대화 조회 → Context 생성 → AI 호출 → 응답 저장**

이라는 전체 흐름부터 이해해보려고 한다.
