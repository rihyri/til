# Day 2. 회고

<br>

오늘은 Spring Boot 애플리케이션의 구조와 JPA에 대해 배웠다.

어제는 Spring이 왜 필요한지와 IoC, DI 같은 기본 개념을 공부했다면, 오늘은 실제 Spring 애플리케이션의 코드가 어떻게 나누어지는지 조금 더 구체적으로 알게 되었다. 

평소에 아무 생각도 없이 사용하던 Controller → Service → Repository로 역할을 나누는 Layered Pattern이 기억에 남았다. 이전에는 단순히 파일을 구분하기 위한 구조라고 생각했는데 각각의 역할을 위하여 나누어지는 디자인 패턴이라는 것을 알게 되었다.

가장 헷갈렸던 부분은 Flyway와 `@Entity`였다.

둘 다 테이블을 만드는 것처럼 보여서 같은 역할이라고 생각했는데, 정리하면서 `@Entity`는 Java 객체와 DB 테이블의 매핑을 정의하고 Flayway는 실제 DB 스키마가 어떻게 변경되었는지를 버전별로 관리한다는 차이를 알게 되었다.

ORM과 JPA도 아직 완전히 익숙하지는 않다. 지금은 **ORM → 객체와 테이블을 연결하는 개념, JPA → Java ORM 표준, Hibernate → JPA 구현체** 정도의 관계를 먼저 기억하려고 한다.

--

혼자 Spring Boot를 공부할 때는 코드를 작성하고 해석하는데 급하여 어떻게 과정이 이루어지고 있을까? 라는 생각을 많이 하지 못했다. 이번 과정을 통해 Spring Boot에 대하여 어떻게 동작하고 있는지 제대로 배워야겠다고 다짐을 하였다.
